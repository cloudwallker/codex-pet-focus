# Codex 原桌宠兼容性

## 当前结论

已实测 Codex `26.908.4834.0`。可以按 WindowsApps 安装路径、进程 ID、可见性、窗口类和置顶透明样式唯一定位原桌宠窗口。随后通过 Windows UI Automation **只读获取唯一宠物图像元素的实际屏幕边界**，供文字横幅跟随。

当前自定义宠物的图像元素名称为 `Takamatsu Tomori 宠物`，实测矩形为 `(-245,150)-(−115,291)`，即 130×141 物理像素。该边界来自可访问性树，不依赖猜测尺寸，也不读取聊天或认证内容。最初仅依赖持久化状态的方案无法获取精灵边界，已由此方案取代。

**自动移动、跳跃、归位门槛未通过，因此没有实现或开放自动动作状态机。** 不修改 Codex 客户端，不移动真实光标，不以整窗上下移动替代跳跃。

## 自动动作失败证据

- 原 overlay HWND `0x30C28`，内容 HWND `0x30C2C`，窗口矩形 `(-552,0)-(0,1080)`。
- 请求右移 20px 后实际矩形为 `(-532,0)-(0,1080)`。Electron 保持屏幕右边缘，结果是缩宽，未完成整体平移；试验结束恢复原矩形。
- 投递 `WM_MOUSEMOVE/WM_MOUSELEAVE` 时，真实光标、前台窗口及最近输入时间未改变，截图出现姿态变化并回到待机。
- 该跳跃试验使用当时尚未验证的精灵范围，不能作为可靠且可重复触发原生 jumping 的通过证据。没有把自然悬停或其他动作算作完成。

原始证据位于开发目录 `artifacts/compatibility/`。原生动画规则由已安装客户端代码确认，但运行时助手不注入、不改写客户端代码。

## 横幅定位的边界

`CodexPetLocator.FindPet()` 返回顶层和内容 HWND、图像及窗口物理像素矩形、Codex 版本。失败可读取 `LastStatus/LastReason`。

仅接受当前已检查的 Codex 包版本；未知版本、窗口歧义、宠物隐藏、UIA 图像缺失或歧义均隐藏横幅。图像必须具有当前中英文宠物可访问名称后缀，完全处于原窗口内，且左上角与保存位置相差不超过 1 像素；其他语言可能暂不可识别。不回退到猜测坐标。UIA 查询应在后台执行，防止外部窗口响应慢阻塞任务面板。

本机已验证副屏负坐标和当前自定义宠物。不同缩放、内置宠物、拔屏及隐藏重开仍需在对应真实环境补充验收。UIA 返回物理屏幕边界，布局代码负责按目标显示器缩放并限制工作区。

## 更新策略

Codex 更新后重新验证。无法识别时保留离线任务与计时，只隐藏横幅并显示原因。完整自动动作需独立重新通过原方案门槛，当前没有强制开启开关。
